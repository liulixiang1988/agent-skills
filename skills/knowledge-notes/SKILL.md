# Knowledge Notes

将当前会话中的知识整理为可独立阅读、后续可复用的中文笔记，保存到用户的 OneDrive Obsidian 知识库。用户指定的主题、范围、目录和语言优先。

## 1. 确定要保存的知识

- 指定主题或“只记录这一部分”时，仅提取该范围；未指定时，提取当前会话中值得复用的概念、原理、操作方法、排障经验和设计取舍。
- 根据当前可见会话和实际读取的材料整理。区分已验证结论、推断和待验证事项，保留适用条件、版本及验证日期等影响复用的限制。
- 写成脱离聊天记录也能理解的知识笔记：交代问题、结论及原因，必要时保留命令、代码、验证方式与易错点。一次会话中的不同知识主题可分成多篇，并相互链接。
- 工作完成清单、绩效素材和待办属于 `work-record` 的用途。仅在用户也要求记录工作时处理这些内容；本技能以知识沉淀为目标。
- 命令示例使用占位符替代密码、令牌、私钥和临时签名 URL。只有会话中真实出现或已核实的来源才能列入参考资料。

范围足够明确即可写入，无需逐次确认标题或分类。若当前上下文缺少用户指的那段知识，只询问缺失的内容。

## 2. 定位知识库与本地规范

技能目录和笔记库是两个独立位置。**无论技能安装在项目、用户还是系统目录，都以当前用户的环境定位笔记库，不依赖当前工作目录，也不硬编码用户名。**

默认知识库：

```text
{USERPROFILE}\OneDrive\文档\notes
```

使用本技能自带的只读解析器：[scripts/Resolve-NotesVault.ps1](scripts/Resolve-NotesVault.ps1)。将 `$skillDir` 设为本次实际加载的 `SKILL.md` 所在绝对目录，再运行：

```powershell
$vault = & (Join-Path $skillDir 'scripts/Resolve-NotesVault.ps1')
# 用户本次明确指定其他知识库时：
$vault = & (Join-Path $skillDir 'scripts/Resolve-NotesVault.ps1') -VaultPath 'D:\Notes'
```

解析顺序：

1. 本次指定的 `-VaultPath`，其次为环境变量 `KNOWLEDGE_NOTES_VAULT`；显式路径必须是已存在的绝对目录，错误时不悄悄切换到其他位置。
2. 默认 `{USERPROFILE}\OneDrive\文档\notes`。
3. 检查 `OneDriveConsumer`、`OneDrive`、`OneDriveCommercial` 和 `{USERPROFILE}\OneDrive` 下的 `文档\notes`、`Documents\notes`，选择唯一含 `.obsidian` 的知识库。

自动发现的目录必须含 `.obsidian`。缺失或多个候选时向用户确认位置；不能在当前项目或未确认的 OneDrive 账户中新建替代库。显式指定的现有目录可不含 `.obsidian`。没有 PowerShell 时按同一规则检查路径。

在知识库和选中的子目录查阅适用的 `AGENTS.md`、`CLAUDE.md` 及其指向的相关规范。**这些文件和现有笔记是目录、标签、元数据约定的依据，每次使用时读取，不将整套约定固化到技能里。** 写标签前，如有 `.claude/rules/tag-registry.md`，先查已有标签；仅按当前任务需要读取索引或其他规则。

## 3. 按主题分类并查重

先查看知识库顶层和相关分类的子目录，再按主题关键词查找笔记文件名及必要的正文。使用 `rg --files` / `rg` 或原生文件工具，将搜索限定在相关分类，排除配置、缓存和附件目录。

按以下优先级确定目标：

1. 用户指定的知识库内目录或现有笔记。
2. 已有同主题笔记所在目录，或语义最接近的现有分类。
3. 没有合适子目录时，在最接近的现有分类下创建一个名称清楚的子目录；已有相近分类时沿用它。跨领域主题选择主要用途所属目录，以内部链接关联其他领域。

例如，**目录存在且内容匹配时**：

| 知识内容 | 优先检查的分类 |
| --- | --- |
| Agent、模型、提示词、技能 | `AI/` 下对应子目录 |
| Azure 服务与平台特有配置 | `Azure/` 下对应服务 |
| 通用 Kubernetes、容器、服务网格 | `Cloud Native/` |
| Git、Shell、操作系统及开发工具 | `Linux & Tools/` |
| 语言及运行时机制 | `Programming Languages/` |
| 架构设计、通用系统设计原则 | `Design/` |
| 内部项目架构、专用流程、项目环境 | `Work/` 下对应项目 |
| 阅读、财经或个人知识 | 对应现有的 `Reading/`、`Finance/` 或 `Personal/` |

通用知识按领域分类；依赖内部项目背景的内容放入项目分类。无需为每次会话新建目录，也不将知识笔记默认放入月度 Work Log 或原始剪藏目录。

写入前读完整的目标笔记及少量相关笔记，确定本次是创建、补充还是无需改动。用户给出的相对目录以知识库为基准；解析最终路径并确认其仍位于选定知识库内，包括目录链接的实际目标。

## 4. 创建或补充笔记

**新笔记**使用清楚的主题名，如 `Git Worktree 使用与清理.md`，避免按会话日期堆积重复主题。文件名应兼容 Windows，避开保留名称和路径字符；同名但不同主题时添加语义限定词。优先沿用本地模板和同目录风格。没有额外规范时，使用以下最小结构，按内容增删正文小节：

```markdown
---
title: "主题名称"
tags:
  - Domain
  - Topic
created: YYYY-MM-DD
updated: YYYY-MM-DD
---

# 主题名称

说明要解决的问题、适用场景和关键结论。

## 原理与方法

解释核心机制或操作步骤，保留必要的命令、示例和验证结果。

## 注意事项

记录限制、失败原因及尚待验证的部分（有内容时才写）。

## 参考与关联

列出实际使用的来源，以及已确认存在的 [[相关笔记]]（有内容时才写）。
```

使用当前本地日期替换日期占位符，并将示例标签替换为库内已有的相关标签；本地要求的字段和标签数量优先。

**已有笔记**保留原有 frontmatter、`created`、正文、链接和用户手写内容，只合并本次知识带来的增量：

- 向相关小节补充，必要时增加小节，并按本地规范维护 `updated` 等修改日期字段。
- 内容已经完整覆盖时跳过，重复调用不新增相同段落或同主题副本。
- 已有结论与本次证据冲突时，说明适用条件、日期及新证据，避免无依据地删除或覆盖旧结论。
- 按现有命名建立 `[[笔记名]]` 链接；重名笔记用知识库相对路径消歧。仅链接已存在或本次创建的目标。
- 只有本地规范要求时，才增量更新相关目录索引；保留现有索引格式。

以 UTF-8 写入，尽量保留已有换行风格。写入前重新检查目标文件是否变化，有变化则重新读取并合并，避免覆盖其他编辑。仅修改本次知识涉及的笔记和必要索引，不批量整理知识库，也不改动 `.obsidian` 配置。

## 5. 验证与反馈

重新读取实际写入的文件，确认内容完整、中文与代码块正常、YAML 有效、引用目标存在，且既有内容得到保留。确认每个请求主题已保存，或有明确的跳过原因。

简短告知创建、补充或已覆盖的知识主题，提供笔记的绝对路径链接；新增分类时说明归类理由。只报告已验证的本地写入结果，不将其描述为已经完成 OneDrive 云端同步。
